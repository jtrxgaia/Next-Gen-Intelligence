# Evidence and confidentiality policy

Allowed publication material: reviewed Markdown reports and JSON benchmark receipts. The user's requested product pictures are stored as image data in JSON receipts to preserve the Markdown/JSON-only repository rule. No executable code, scripts, binaries, source maps, models, algorithms, proprietary logic, raw prompts, private memory, credentials, host paths, internal implementation links or dataset answers may enter this repository.

Every upload must be staged by exact allowlisted filename and inspected before commit. Never use a recursive copy of the engine estate. File extension alone does not make content safe: review Markdown and JSON for embedded code and internal methods. Future additions require the same review. This is a publication policy, not an installed server-side enforcement mechanism.

Keep benchmark modes, splits and attempts distinct. Public training results are development measurements. Fixture results are harness validation. Hidden or sealed evaluation claims require verified isolation and provenance. Unknown values remain null or explicitly UNKNOWN. Never turn a missing metric into zero.

AI-tool authorship must be labeled. Do not imply institutional certification by Google DeepMind, OpenAI, ARC Prize or another organization merely because its software was used. No test answers are published.

Do not change repository visibility, add collaborators or publish releases without the owner's explicit instruction. Private GitHub storage transmits these reviewed artifacts to GitHub; private visibility does not mean exclusively local storage.

Use dated correction reports instead of rewriting a historical measurement. Preserve original private artifacts locally; publish only sanitized receipts. SHA-256 checksums attest to content identity, not truth.
